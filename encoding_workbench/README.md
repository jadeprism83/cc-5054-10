# 短片编码方案可视化工作台

为一部三段式短片（动画标题 / 细密织物 / 长静景）实测编码参数、绘制率失真前沿，
并在「成片总字节上限 + 各段最低质量」双约束下选择编码组合的端到端工作台。

## 流水线

```
generate_sources.py   生成 3 段 1920x1080@30fps、4s 的 FFV1 无损母版
encode_grid.py        3 段 × 3 分辨率(1080p/720p/480p) × 6 质量档(CRF18..43+码率上限)
                      + 每段 3 个故意失败任务；共 63 个任务，结果写入 SQLite
selection.py          Pareto 前沿、逐段贪心分配、全片联合 DP（多选背包）
mux_deliverables.py   入选段落流拷贝为独立 MP4，concat 为全片 MKV，另出 720p 预览 MP4
budget_gate.py        封装后若超预算，自动收紧预算回到选择步骤重排；不可行则明确报错
app.py                标准库 http.server 可视化（端口 8765）
```

一键运行：`./run_pipeline.sh`（已完成的编码任务会跳过，缓存在 SQLite 中）。

## 质量测量口径

所有候选都解码后**统一 lanczos 回缩到 1920x1080**，再与母版做逐帧 SSIM/PSNR，
因此不同分辨率的点可以画在同一组坐标轴上。同时保留文件总字节与纯视频码流字节
（ffprobe 逐包求和），两者之差即容器开销。

## 界面页面

| 路由 | 内容 |
| --- | --- |
| `/` | 三段实测率失真前沿（Pareto 点、非单调测量、质量门槛线、入选白圈）+ 贪心/联合对比 |
| `/compare` | 任选两个候选（入选 vs 落选）双播放器对看，支持同步播放，显示 SSIM/体积差值 |
| `/failures` | 9 个保留的编码失败案例（奇数尺寸、非法 preset、越界 CRF）与原始 ffmpeg 日志 |
| `/deliverable` | 可播放成品、预算校验、逐段容器开销与全片 MKV/预览 MP4 开销 |
| `/reselect` | 约束可行性试验台：任意输入字节上限，实时演示不可行组合与可行性下界 |

## 贪心与联合为何会相反（本数据集实测）

预算 387,715 B、各段 SSIM ≥ 0.990：

- **逐段贪心**从最便宜合格方案起步，反复购买「每字节 SSIM 增益」最高的升级，
  预算被静景/标题的廉价小升级占满，织物段无法跨档；总 SSIM 2.98809。
- **全片联合 DP** 允许拆东墙补西墙：把静景从 `480p_q4_fair` 退回 `480p_q6_extreme`
  省 7,645 B，把标题升级到 `1080p_q4_fair`，总 SSIM 提升到 2.98814。

## 保留的异常示例

- *非单调测量*：例如织物段 720p_q6（35 KB）SSIM 0.934 低于 480p_q5（30 KB）0.962，
  图中以紫色点标出，前沿只接受真正不被支配的点。
- *编码失败*：奇数宽度 yuv420p 拒绝、x264 未知 preset、libaom CRF=99 越界。
- *不可行组合*：预算低于 374,074 B（各段达标最便宜组合之和）时两个求解器都报告无解。
- *超限重排*：`budget_gate.py` 实测过一轮「超出 363 B → 收紧预算 → 第二轮通过」。

## 外部依赖

- ffmpeg/ffprobe：静态构建放在 `../tools/ffmpeg-7.0.2-amd64-static/`（含 libx264、libaom）
- Python 3.11 + Pillow（仅生成标题帧用到；其余全部标准库）

## 可撤销早停配置搜索器（`/search`）

针对一段**片头长期静止、中部突然切入细密运动**的对抗素材（9s 静景 + 4s 织物 +
2s 短促高运动镜头），验证「按片头估算的候选排名与整片相反」时，早停决策如何可撤销。
一键运行：`./run_search_pipeline.sh`（编码缓存落在 `out/search/search.sqlite3`，
重跑只补缺失的窗口/完整编码）。

| 模块 | 职责 |
| --- | --- |
| `generate_search_sources.py` | 纯 ffmpeg geq 合成三个 FFV1 母版镜头（无需 Pillow） |
| `search_common.py` | 镜头/窗口/配置网格/两套播放次序/镜头级最低质量约束 |
| `search_encode.py` | 30 帧窗口编码 + 逐帧 SSIM（回缩 1080p 统一口径）与整镜头完整编码 |
| `searcher.py` | 分层抽样、不确定区间追加、R1/R2 淘汰账本、锁定补码、反例重开、穷举审计 |
| `search_panel.py` | 搜索面板：证据分级、淘汰理由重建、锁定按钮、漏解与成本审计 |
| `run_search_demo.py` | 两种抽样策略 × 两种次序 + 穷举前沿 + 锁定反例的无头演示 |
| `tests_searcher_logic.py` | 不依赖 ffmpeg 的合成数据机制测试（`python3 -I`） |

### 决策口径

- **抽样范围**：每个镜头切成 30 帧窗口；`head_first` 按整片顺序逐窗推进，
  `stratified` 先保证每个镜头各取一窗再追加。每次淘汰都绑定具体窗口清单与帧范围。
- **不确定区间**：镜头级 SSIM 用窗口间标准差构造 95% CI；只有当候选的**上限**
  低于门槛（R1）或对手的 SSIM 下界/字节上界同时支配（R2）才允许淘汰。
- **预算追加**：初始窗口用完后，剩余预算按「区间半宽 + 距门槛压力」逐窗追加。
- **可撤销**：面板可锁住任一被排除配置补做整片完整编码；若完整编码构成反例，
  同一假设 ID 下淘汰的全部候选自动重新开放。完整编码按配置白名单摄入——搜索 run
  只会挂载自己锁定补码的那一个配置，共享缓存里穷举参照的完整编码不会泄漏成它的证据；
  R2 反例所需的对手完整编码从库中实时读取并标注 `measured_full_from_shared_store`，
  不写入该 run 的候选状态。
- **证据三态**：`measured_full`（完整实测）、`measured_windows`（窗口实测）、
  `estimated`（抽样外推）在界面与 JSON 中分级标注，预测值禁止冒充完整编码结果。
  面板加载时 JSON 的字符串键会转回整数索引，保证重开页面与实时 run 同口径。
- **独立质量约束**：短促高运动镜头 `burst` 使用更严的独立 SSIM 下限（0.930），
  普通镜头为 0.985；演示先把它放在片中部，再移到素材最末端对比抽样次序影响。
- **审计**：以 18 配置 × 3 镜头全部完整编码的小规模穷举率失真前沿为参照，
  区分「当前仍漏解」与「锁定救回的前沿解」（曾被过早放弃、靠补码反例重开），
  并列出锁定补算帧数（新增编码 / 缓存复用拆分）与相对穷举真正节省的编码帧数
  （只认真实跑过的帧，预测帧不计入）。
