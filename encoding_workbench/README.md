# 短片编码方案可视化工作台

为一部三段式短片（动画标题 / 细密织物 / 长静景）实测编码参数、绘制率失真前沿，
并在「成片总字节上限 + 各段最低质量」双约束下选择编码组合的端到端工作台。

## 流水线

```
generate_sources.py   生成 3 段 1920x1080@30fps、4s 的 FFV1 无损母版
encode_grid.py        3 段 × 3 分辨率(1080p/720p/480p) × 6 质量档(CRF18..43+码率上限)
                      + 每段 3 个故意失败任务；共 63 个任务，结果写入 SQLite
selection.py          Pareto 前沿、逐段贪心分配、全片联合 DP（多选背包）
mux_deliverables.py   入选段落流拷贝为独立 MP4，concat 为全片 MKV，另出 720p 预览 MP4
budget_gate.py        封装后若超预算，自动收紧预算回到选择步骤重排；不可行则明确报错
app.py                标准库 http.server 可视化（端口 8765）
```

一键运行：`./run_pipeline.sh`（已完成的编码任务会跳过，缓存在 SQLite 中）。

## 质量测量口径

所有候选都解码后**统一 lanczos 回缩到 1920x1080**，再与母版做逐帧 SSIM/PSNR，
因此不同分辨率的点可以画在同一组坐标轴上。同时保留文件总字节与纯视频码流字节
（ffprobe 逐包求和），两者之差即容器开销。

## 界面页面

| 路由 | 内容 |
| --- | --- |
| `/` | 三段实测率失真前沿（Pareto 点、非单调测量、质量门槛线、入选白圈）+ 贪心/联合对比 |
| `/compare` | 任选两个候选（入选 vs 落选）双播放器对看，支持同步播放，显示 SSIM/体积差值 |
| `/failures` | 9 个保留的编码失败案例（奇数尺寸、非法 preset、越界 CRF）与原始 ffmpeg 日志 |
| `/deliverable` | 可播放成品、预算校验、逐段容器开销与全片 MKV/预览 MP4 开销 |
| `/reselect` | 约束可行性试验台：任意输入字节上限，实时演示不可行组合与可行性下界 |

## 贪心与联合为何会相反（本数据集实测）

预算 387,715 B、各段 SSIM ≥ 0.990：

- **逐段贪心**从最便宜合格方案起步，反复购买「每字节 SSIM 增益」最高的升级，
  预算被静景/标题的廉价小升级占满，织物段无法跨档；总 SSIM 2.98809。
- **全片联合 DP** 允许拆东墙补西墙：把静景从 `480p_q4_fair` 退回 `480p_q6_extreme`
  省 7,645 B，把标题升级到 `1080p_q4_fair`，总 SSIM 提升到 2.98814。

## 保留的异常示例

- *非单调测量*：例如织物段 720p_q6（35 KB）SSIM 0.934 低于 480p_q5（30 KB）0.962，
  图中以紫色点标出，前沿只接受真正不被支配的点。
- *编码失败*：奇数宽度 yuv420p 拒绝、x264 未知 preset、libaom CRF=99 越界。
- *不可行组合*：预算低于 374,074 B（各段达标最便宜组合之和）时两个求解器都报告无解。
- *超限重排*：`budget_gate.py` 实测过一轮「超出 363 B → 收紧预算 → 第二轮通过」。
